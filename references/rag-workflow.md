# Search a literature collection with available tools

Use for cross-paper questions or library retrieval within the current manuscript's
scope. This module describes a workflow; it does not install a retrieval service
or supply a default paper collection. Select sources from the current task.

## Start with the smallest usable approach

| Available material | Useful work | Limit |
|---|---|---|
| PDFs or extracted text | Read/search relevant sections with file/PDF tools | OCR, figures and tables may require rendered inspection |
| Existing library/index | Use its actual search and source locators | Ranking is not evidence support |
| BibTeX/RIS/metadata | Identify and organize candidates; locate accessible originals | Metadata alone cannot establish study findings |
| Excerpts or notes | Analyze the supplied content, distinguishing quotations from summaries | Do not claim full-paper verification |
| No needed source content | Give a retrieval plan or clearly provisional reasoning | Do not fabricate search or verification |

Reuse existing folders and bibliography keys. No manual index, embedding model or
vector database is required to answer a small collection question.
Create a persistent index only when the user requests it for their current
literature work. A collection supplied for skill development or evaluation is
not authorization to turn it into a reusable manuscript knowledge base.
Do not upload private papers to an external service merely to enable retrieval.

## Retrieval with provenance

Use [rag-retrieval](rag-retrieval.md) to form neutral and competing queries.
Keep source/version, page/section or a recoverable file/chunk locator.
Read surrounding context; inspect original pages for uncertain OCR/numbers.
Do not report counts of searched/read documents unless actually tracked.

Before writing a citation apply [rag-verification](rag-verification.md) and the
shared [evidence standard](evidence-grading.md).
A cross-paper answer should explain compatible and conflicting findings, differences
in population/design/measurement and the actual coverage inspected.

## Reusable organization

For repeated work use [survey-workspace](survey-workspace.md) and
[paper-pool](paper-pool.md). Separate candidate discovery from inspected evidence.
Preserve original files and source links; retain versions rather than silently
merging a working paper with a revised journal article.

Deliver the answer and locatable evidence, with limits where material. Avoid
technical architecture, similarity scores or infrastructure setup in the user's
writing workflow unless they asked to build that infrastructure.
