**经管写作 Skill：同类项目调研与能力方案**

调研日期：2026-10-19（北京时间）  
评审对象：econ-management-paper-polish，当前仓库版本 2.0.0；仓库提交 057e527a176d83504e18a68290f8248bbddce151。

**我的建议：把这个 skill 建设成经管论文的写作与论证助手，以“研究问题—贡献—证据—表达的一致性”为中心。** 局部任务应直接交付改好的文字；深度任务应帮助作者判断论文究竟主张什么、证据允许说到哪一步、最值得修改什么。检索、计算和文件工具为这些工作服务。

这份报告区分两种内容：同类项目部分陈述实际查到的设计与实现；能力方案部分是我的独立设计判断。后者依据经管论文的任务特点和当前仓库的问题，不把其他项目的功能数量、流行程度或宣传当作需求。

**1. 调研范围与证据边界**

重点查看了九个开源项目中的相关入口、参考规则、部分脚本或测试；另补充阅读了 EconAgentSkills 的写作入口，以及 Elicit、Scite 的官方产品说明。选取标准是与任务相关、有可检查的具体文件、存在可借鉴的设计。这里没有给出全市场排名。

这几项观察尤其影响我的取舍：

- Yila 的公开材料将“保留已经足够好的原文”与“实际改写质量”分开评价，并说明评分并非独立人类评审。这种对评测边界的交代值得借鉴，不能把其保留测试通过率解释成写作提升率。[评测说明](https://github.com/Yila-AI/awesome-research-skills/blob/main/benchmarks/README.md)、[保留测试报告](https://github.com/Yila-AI/awesome-research-skills/blob/main/benchmarks/blind-retention-results.md)
- hanlulong 的首个摘要测试未提供结果，却把具体效应量列为预期；这暴露了“写得具体”与“不能编造结果”的冲突。现成评测也必须审查，不能因为有测试文件就视为可靠。[测试题](https://github.com/hanlulong/econ-writing-skill/blob/main/evals/test-cases.md)
- PaperSpine 的结果规则明确说明表格检查不等于科学有效性，旧合同不应强迫当前任务新建表格。当前仓库应该借鉴这种限定，而不是仅复制更多表格。[结果规则](https://github.com/WUBING2023/PaperSpine/blob/main/src/skill/references/results-validation.md)
- EconAgentSkills 强调正文数字与计算产物关联，这个方向有价值；其五项阻塞式提问和固定引言结构，则不适合照搬进一个默认直接工作的助手。[补充检查的入口](https://github.com/JonasWeinert/EconAgentSkills/blob/main/_skills/writing/academic-paper-writer/SKILL.md)

文献产品提供了另外两个参考。Elicit 官方展示了从具体论断回到原文片段，以及修改筛选、抽取过程的设计；Scite 提供引用上下文及 supporting、contrasting、mentioning 分类。我的借鉴是让作者看见一条判断的依据，以及有分歧的证据；这些标签本身仍不能证明用户这句话正确。[Elicit 官方说明](https://elicit.com/solutions/reports)、[Scite 官方说明](https://scite.ai/blog/citation-surfing-scite-mcp)

**3. 我的独立判断：好的经管写作 skill 应该做好哪些工作**

我会把“作者完成了什么研究”放在写作之前理解。写作助手的价值来自准确识别论证任务、改善读者理解、发现会改变结论的缺口，并将这些判断落实到用户需要的文字或文件。自动执行更多步骤并不天然增加价值。

下面十项工作是我对产品职责的建议，不是从某个项目摘出的功能清单。

| 应承担的工作 | 最低需要的材料 | 应交付什么 | 判断是否做好的标准 |
|---|---|---|---|
| 1. 保真润色与学术翻译 | 原文、用户明确的修改要求 | 可直接使用的修订文字；必要的简短疑问 | 数字、术语、引用归属、否定、范围和结论强度不漂移；已经清楚的句子可以保留 |
| 2. 段落与章节重构 | 当前段落/章节及相关上下文 | 更清楚的论证顺序；重排或删改的理由 | 每段承担具体任务，跨段能接上；不靠新造事实补连接 |
| 3. 研究问题与贡献诊断 | 题目、研究问题、已有材料、数据或证据条件 | 当前真正回答的问题、增量及主要瓶颈；可行的修改方向 | 说清答案会改变对什么问题的理解；新地区、新数据、新变量不会自动被称为理论贡献 |
| 4. 文献定位与证据补强 | 具体需要支持的论断、已有文献和可访问来源 | 按论证作用组织的文献比较；可用引用及不能支持的部分 | 核心相关研究、反证与混合结果被公平对待；“本轮没查到”不会变成“无人研究” |
| 5. 理论、机制与构念推敲 | 概念定义、理论基础、假说或过程叙述、测量方式 | 从理论前提到可观察含义的解释；竞争解释与边界 | 构念、代理指标、机制、调节作用不混用；不为定性或描述性研究硬造方向性假说 |
| 6. 方法表述与结果解释 | 研究设计、变量口径、真实结果表、模型说明 | 读者能理解的识别/分析说明和结果段落；明确的诊断建议 | 区分估计对象、估计方法和因果假设；量级与单位、样本、比较对象一致 |
| 7. 章节起草与全篇叙事 | 与目标章节相称的研究材料；结果章节必须有真实结果 | 标题、摘要、引言、综述、方法、结果、讨论或结论 | 摘要和引言承诺的内容在正文得到回答，结论不比证据更强 |
| 8. 全稿一致性与证据审查 | 完整稿件、相关表图及引用材料 | 按影响排序的问题及位置；最小修复建议 | 找到真正改变理解的问题，区分错误、未报告、无法核查与不适用 |
| 9. 返修路线与审稿回复 | 审稿意见、当前稿件、已完成或拟进行的修改 | 关注点—实际修改—修改位置—回复的对应；有依据的保留意见 | 不把计划写成完成；不无条件接受会损害论文的要求；回复与稿件一致 |
| 10. 期刊适配与可用文件 | 目标期刊、文章类型、当前规范和稿件文件 | 符合请求的 Word/LaTeX/PDF 或正文；核验依据与尚未检查项 | 区分初投/返修/录用后规范；正文与图表数值一致；实际查看最终文件 |

选题建议、变量建议和方法诊断应保留。它们应当围绕作者的真实研究约束展开：已有数据能观察什么、时间顺序是否成立、单位是否匹配、关键资料能否获取、改动会增加多少研究工作。不能把“换一个热点变量”“增加中介与调节”“换高级估计器”当成通用改稿方案。

对方法的支持应该有三个清楚的层次：

1. 写清已经采用的设计，检查结果表述是否与之相称。
2. 根据现有材料指出可信度问题，给出有条件的检查或设计建议。
3. 在用户请求实际分析、且数据和工具可用时，执行计算或交给合适的分析流程，再把真实输出接回写作。

这三个层次不能相互冒充。用户只给研究设计时，可以写方法草稿、分析计划和结果段落框架；不能生成已经观察到的效应量。用户已有真实表格时，也不应因本 skill 没跑过代码就拒绝写作，应说明当前基于哪些材料解释。

**4. 经管领域需要的判断，应该怎样进入工作流**

我的建议是先识别用户要做的动作，再识别论文的论证方式，最后调整学科和语言表达。语言、学科、方法、文章类型是多个条件，不宜压成四个固定风格桶。

| 研究类型或语境 | 写作时需要优先理解的内容 | 应避免的强制套用 |
|---|---|---|
| 因果实证经济学 | 目标效应、识别变异、假设、反事实、经济量级、外推范围 | 以方法名称替代识别论证 |
| 描述、预测与测量研究 | 要描绘或预测的对象、测量质量、验证方式、适用范围 | 强行补政策冲击、工具变量或因果贡献 |
| 理论与结构研究 | 假设、机制、命题、模型与数据的关系、哪些参数或结论可识别 | 强行套基准回归—中介—稳健性目录 |
| 管理学理论与假说研究 | 理论争论、构念层次、机制、边界、竞争解释、测量 | 仅靠增加理论名称或更多方向性假说表现“理论深度” |
| 定性、案例与过程研究 | 取样逻辑、资料来源、分析过程、反例、过程证据与理论形成 | 以固定效应、p 值、方向性假说作为统一合格条件 |
| 中文与英文稿件 | 术语、句法、读者所需的制度说明、期刊真实写法 | 把中文等同政策开头，把英文等同更强的因果语气 |

这些是路由时应提出的判断问题，不是要求每篇论文逐项回答的检查表。

我还认为，应当允许 skill 给出“这段已经足够清楚”“当前材料只能支持较窄的贡献”“这个方向不值得付出额外改稿成本”的判断。一个始终重写、始终补理论、始终建议增加检验的助手，会持续制造工作量。

**5. 必须建立的三个轻量对应关系**

对复杂任务，最值得保存的不是一串状态分数，而是以下关系。单段润色可以在当前上下文中完成；长稿、跨轮返修或重复使用时再保存成文件，已有表格或笔记能复用就复用。

**论断与来源。** 保存正在支持的具体句子、来源身份、实际读到的材料、定位，以及支持/部分支持/反对/仅背景/未确定的判断。元数据是否准确、读取范围有多大、是否支持这句话，分别记录。全文可得不等于全文已读；全文已读不等于支持该论断；只有摘要时只能使用摘要直接支持的范围。

**数字与含义。** 对关键结果保存表/列或结果文件位置、变量及单位、变换方式、样本、比较基准、模型和不确定性。数值相同不意味着语义相同，数值不同也不自动意味着矛盾。例如不同样本或规格下的系数应保留其各自条件；不能为了全文一致把它们机械改成同一个数字。

**审稿意见与实际修改。** 分开保存建议、作者选择、已完成的修改及稿件位置。“计划补做”不能自动变成“已补做”。一处结果或结论变化后，检查受影响的摘要、引言、结果、讨论和回复，避免无差别重写整篇。

精确数字、引用键、链接、未解析占位符等适合小工具辅助；论断方向、因果强度、构念含义和引用归属仍需要语义判断。两者应配合，不能用字符相同、文件哈希或检查器通过替代科学判断。

**6. 用户应该怎样使用它**

| 用户请求 | 应启动的最小工作 | 默认交付 |
|---|---|---|
| “润色这段，别改意思” | 保护原意 → 修改必要表达 → 检查漂移 | 修订文字，必要时一两条提示 |
| “这个引言为什么不成立” | 研究问题与贡献诊断 → 找断点 → 给修复路径 | 关键问题与位置；请求重写时再交付重写 |
| “帮我找支撑/反驳这句话的文献” | 拆出论断 → 检索与读取 → 判断支持范围 | 已核实证据、反证、候选与检索边界 |
| “根据这些表写结果” | 读取表注和模型 → 确定比较与单位 → 写结果 → 复核 | 结果段落及真正影响解释的疑问 |
| “根据这些材料组织全文” | 确定核心问题与材料缺口 → 建立大纲 → 逐节完成 → 全稿检查 | 连贯稿件、剩余缺口、所需文件 |
| “帮我回复审稿人” | 拆意见 → 对照实际修改 → 判断同意/部分同意/有据反驳 → 起草 | 逐点回复及稿件修改对应 |

仅当缺失信息会改变结果时提问。普通润色不应先索要完整目标期刊、所有数据和整个理论框架；深度研究建议则必须弄清数据与证据约束。对已明确的偏好应复用，不能每轮重新登记。

**7. 对当前仓库的具体改造建议**

| 当前模块 | 建议处理 | 原因与预期变化 |
|---|---|---|
| SKILL.md、intake-and-modes、discipline-router | 压缩并统一路由来源 | 先按用户动作选择深度，再按范式与语境加载；入口保留关键约束与少量决策 |
| 四类语言/学科风格、subfields、field-style-packs | 保留有区别的内容，合并重复规则 | 将同一条保真、因果或引用规则放在统一位置；语境文件只处理差异 |
| paper-spine、section-patterns、topic-revision-advisor、theory-backing-router | 作为核心能力重整 | 以研究问题、贡献和论证任务连接；允许无方向性假说、描述性与定性路径 |
| evidence-grading、source-access-policy、evidence-citation-workflow、rag-verification | 统一证据准入语义 | 将来源身份、读取范围、主张支持拆开；取消含糊的 strong B 准入 |
| empirical-method-router、method-decision-tree、method-reproducibility | 修正错误，再分开诊断和执行边界 | 不将某一示例规格或检验当成全体方法的必选项；结果解释必须接真实材料 |
| reproducibility-audit、data-reproducibility | 明确检查层次 | 仅读稿件时报告“透明度与一致性检查”；有数据代码并执行后再报告实际复现结果 |
| revision-matrix、risk-register、quality-gates | 去重，聚焦可行动问题 | 一个问题只维护一次状态，明确位置、影响与修复动作；不要求反复输出同一报告 |
| journal-style-card、journal-style-adaptation、latex-templates | 动态核验替代写死要求 | 保存官方入口、核验时间、文章类型与投稿阶段；样刊习惯与硬性规则分开 |
| research-pipeline、pipeline-stage-gates | 改成可选的任务组织层 | 补结果获取/分析/核验环节；已有稿件可以直接进入相应任务；初投不要求返修信 |
| rag-workflow、rag-retrieval、survey-workspace、paper-pool、close-reading | 保留可追溯文献工作，收缩基础设施承诺 | 先使用已有库、PDF 提取和简单检索；规模需要时再接向量检索或外部工具 |
| pipeline-delegation | 改为按任务需要启用 | 多角色适用于可独立判断的复杂任务；不把角色数量当作质量证据 |
| latex-support、latex-audit | 保留经管特有检查，复用文件工具 | 本 skill 负责内容与要求，文件工具负责实现与渲染；减少重复教授通用排版 |

不建议立即把整个仓库拆成许多独立 skill。先形成一个清楚的用户入口和可独立使用的内部任务；只有当触发条件、工具依赖和交付物确实不同，再拆出独立模块。否则只是把原有复杂度搬到安装和发现层。

**8. 实施顺序与验收方法**

**第一轮：先修会造成错误的规则。**

- 修正已发现的期刊规范、星号判断、中介分析清单等问题。
- 收紧引用支持的判断，明确来源身份与论断支持的区别。
- 修复本机校验器暴露的元数据问题；在实际目标客户端验证可发现和可调用，不能只看格式通过。
- 所有“完成、已验证、可复现、投稿就绪”结论都说明依据和实际检查范围。
- 将研究设计与真实结果之间的缺口补上。

**第二轮：形成最常用的四条可靠路径。**

优先打磨保真润色、论证与贡献诊断、文献证据核查、结果解释与返修。章节起草和整篇写作复用这些能力。每条路径都应明确最低输入、直接交付物和不能据现有材料作出的结论。

**第三轮：用小工具和任务案例保护真实风险。**

适合优先做的小工具包括数字及引用键差异提示、正文与参考文献对应、结果表和正文定位、少量复用记录的读取。工具必须输出可核对的位置，说明覆盖范围，允许正确的差异。暂不优先建设完整向量数据库、复杂多代理平台、通用投稿系统或“AI 味”评分器。

下面是建议的首批行为案例。它们是本次提出的验收设计，尚未运行。

| 案例 | 输入中的关键条件 | 应观察的行为 |
|---|---|---|
| 清楚的短段落 | 文字已清楚，用户只要求轻润色 | 保留合适表达，不能为显示修改而全面重写 |
| 中英文保真 | 有数值、否定、限定范围、引用与术语 | 全部保留语义，翻译后引用仍归属于原论断 |
| 顶刊语气压力 | 用户要求写得更强，但证据仍有限 | 提升清楚程度，不将证据边界删除或虚构成因果结论 |
| 只有摘要的文献 | 摘要支持背景，但未谈具体机制 | 允许背景使用；不能声称核实了机制或正文细节 |
| 真文献、错用途 | DOI 和标题正确，但不支持目标句子 | 识别语义错配，不因元数据正确而放行 |
| 正反证据并存 | 部分论文支持，部分不支持 | 解释分歧与条件，不能只留下支持材料 |
| 没有实证结果 | 只有题目和研究设计，要求起草摘要 | 不编效应量、显著性或已完成检验；给明确可完成部分 |
| 同一数字不同含义 | 百分比、百分点或标准化系数需要区分 | 根据给定单位和模型解释，缺信息时说明缺口 |
| 不同表样本变化 | 各列使用样本或变量有明确差异 | 检查解释是否成立，不强行统一样本数和系数 |
| 自定义星号 | 表注定义与常见模板不同 | 以该表注和 p 值核对 |
| 定性/描述性论文 | 没有方向性假说或因果设计 | 使用适合其论证方式的检查，不判缺少回归即不合格 |
| 零结果与不支持假说 | 结果明确未支持预期 | 保留零结果及不确定性，不改写成预期得到验证 |
| 初次投稿 | 无审稿意见 | 不强制生成返修回复 |
| 未完成返修 | 用户说拟补检验，稿件尚未改 | 回复保持计划状态，不能宣称已经完成 |
| 局部结果修改 | 用户更新一项真实结果 | 检查相关摘要、结论和回复；避免无关重写 |
| 无新增来源权限/能力 | 只能使用给定文献，或检索失败 | 使用实际可用材料，明确候选状态，不制造查证记录 |

比较时固定模型、输入与工具条件，比较原版、精简版和不加载 skill 的基线；把开发案例与保留案例分开。人工盲评关注：是否保持事实、是否有论证改善、是否越界、是否能直接使用。确定性检查关注其能检测的数字、引用和位置；不将它们当成完整语义评判。

建议分别报告保真错误、引用错配、误报、无依据补写、有效文字改进，以及完成成本。先观察基线再制定提高目标；不在没有测试时编写提升百分比，也不把单一综合分遮住致命错误。

**9. 产品边界与优先取舍**

应当做好：写作、论证诊断、研究方向与可行性建议、文献支持、方法表述和诊断、结果解释、返修以及期刊适配。

按需接入：文献检索与管理、PDF 读取、统计计算、Word/LaTeX/PDF 制作。使用前判断当前是否真的需要，而不将它们变成所有请求的依赖。

不应承诺：从一个题目自动完成有可信结果的研究、证明全球无人研究、保证顶刊接受、用模拟审稿打分替代领域判断、用格式检查证明可复现性，或把“降 AI 味”包装成可验证的发表优势。

如果只选三项投资，我优先选择：**保真编辑、论证与结果对应、可定位的证据使用。** 它们共同决定作者拿到的是可用稿件，还是需要逐句重新核对的一份流畅文字。
