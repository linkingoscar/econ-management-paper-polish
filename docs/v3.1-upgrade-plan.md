# v3.1 升级计划：写作可靠性与返修闭环

> 状态：In progress / alpha implementation
> 基线：v3.0.0-alpha.1
> 产品定位：经管类论文写作、论证、期刊适配与返修 Skill
> 外部调研依据：[v3.1 外部项目调研报告](v3.1-landscape-research.md)
> 重要边界：研究检索、RAG、方法安全和多代理均服务于写作，不把本项目扩张为通用自主科研平台。

当前实现状态：M0/M1 的可运行基础，以及 M2/M3 的第一批写作安全闸门已进入
本地 v3.1 alpha：corpus manifest、style card/profile、paper spine、claim–evidence
检查、review ledger、风险预路由、受保护 patch、meaning gate、method-language
gate、LaTeX compile guard、issue recall、动态 style profile 人工确认、provenance
扫描和离线写作评测。更深方法 fixture、完整的 revision apply/rollback、真实用户
论文 dogfooding 和动态期刊语义适配仍是后续工作。

## 0. 2026-08-04 实施质量复核

### 0.1 总体判断

当前 v3.1 **达到了“工程型 alpha 基座”的预期，但没有达到“完整 v3.1 写作产品”
的发布预期**。

这个判断分三层：

1. **工程可靠性：基本达到 alpha 预期，但包装校验尚有一项阻塞。** 已有职责分离
   的 schema、脚本、JSON 输出、退出码、离线 fixture、CI 和能力降级；v3.0 smoke
   8 项、extended 10 项、v3.1 writing 15 项当前均通过，仓库自带契约也通过。
   `SKILL.md` 保持在 500 行以内，并通过 14 个 v3 reference pack 和根级写作契约
   实现渐进加载；但 Skill Creator 的 `quick_validate.py` 当前报告 frontmatter
   description 为 1201 字符，超过 1024 字符上限，因此 Skill 包装还不能算完全合格。
2. **写作安全基础：部分达到预期。** 数字/变量/引用保护、词法 meaning gate、
   方法越界短语、LaTeX 结构、issue recall 和动态 profile 人工确认已经能阻断
   一批明确错误；但多数能力仍是“检查器或脚手架”，不能证明语义等价、方法正确、
   期刊适配有效或审稿问题已经实质解决。
3. **端到端写作效果：尚未达到预期。** 当前没有把真实论文稳定地串成
   `intake → paper spine → evidence → style profile → bounded revision → review closure`
   的工作区流程；没有真实论文 dogfooding、gold/mutation 评测和作者人工 rubric，
   因而不能据现有 100% 合成测试通过率宣称达到 v3.1 发布门槛。

因此，当前版本适合标记为 `v3.1.0-alpha.1` 或后续 alpha，不应升级为 beta/稳定版。
下一阶段的目标不是继续增加孤立检查器，而是把已有检查器串成可恢复、可审计、
能产生真实写作收益的最小闭环。

### 0.5 下一阶段工作：按发布阻塞程度排序

#### R1：先形成一个真正可跑通的写作闭环

新增最小 `paper-workspace/` 和单一串行 orchestrator，把现有脚本连起来，而不是
再增加平行的独立模块。

最小产物：

* `intake.json`：Router 2.0、判断依据、置信度和用户 override；
* `paper-spine.json`：从作者文本生成的候选 claim/section/argument map，必须等待确认；
* `protected-snapshot.json`：数字、变量、引用、公式、表图和作者锁定片段；
* `revision-journal.jsonl`：run id、输入 hash、issue/claim、候选 patch、每道 gate 和结果；
* `capability-report.json`：本次实际执行、跳过、降级和输出上限；
* `checkpoint.json`：最后一个通过的 gate 和可恢复位置。

验收：从一段论文或一个 reviewer comment 出发，可以生成候选修改、运行所有适用
gate、更新 ledger，并在失败后从 checkpoint 恢复；默认不覆盖论文。

#### R2：把 Evidence Pack 升级成真正的写作证据图

* 将 `source_id` 与 `claim_id` 分离，支持一个来源支持多个 claim、一个 claim 由多个
  来源支持；
* direct citation 强制 `locator`、`support_scope`、`limitations`、`checked_at` 和
  `allowed_use`；
* 增加 `verified / metadata-only / candidate / rejected / stale` 状态及拒收日志；
* 对 DOI 格式、假 DOI、重复来源、过期来源和 metadata-only 直接引用增加失败 fixture；
* 将文献综述、方法段落和结果解释中的新增外部主张绑定到证据记录。

验收：任何新增外部主张都能从句子/claim 追到 source 和 locator；删除 source 时能列出
受影响的 claim；candidate/metadata-only 不会被当作全文证据。

#### R3：完成动态期刊适配，而不止生成统计 profile

* corpus manifest 将授权状态改成受控枚举，授权不明、metadata-only 和不可读文件不得
  进入 full-text style extraction；
* 增加目标期刊最小样本量、来源角色、时间窗、stale 和低置信度 gate；
* style profile 按 target/field/author guideline 分层聚合，而不是把所有 card 等权平均；
* 增加 n-gram/长片段重合审计，保证修订候选没有复制语料原句或独特表达；
* 生成 section-specific dynamic profile，并把每条建议绑定到 style-card locator；
* 用 profile 完成一次有限章节修订，并写入 revision journal。

验收：小样本、冲突语料、过期指南、授权不明和原句复制均有正反 fixture；profile
通过人工 gate 后仍不能越过 P1 保护字段。

#### R4：把方法正则升级成“风险卡 + 改写 + 证据 + 评测”

优先覆盖计划已承诺的方法组：staggered DID/异质性效应、连续处理、Bartik、CATE、
描述性/因果中介、quantile/Oaxaca，以及 survey、实验、定性和混合方法。

每个方法组必须有：

* 数据结构、识别变异、estimand、假设、诊断、剩余威胁、报告要求；
* 至少一个经核验的权威来源和核验日期；
* 明确越界负例、合格正常例、边界例和保守改写；
* 中文/英文各至少一个 fixture；
* 误报和漏报记录，而不只统计“脚本有没有报错”。

验收：方法建议不从方法名直接跳到因果结论；越界表述被拦截后，输出能说明为什么、
如何保守改写、还需要作者补什么。

#### R5：完成真正的 Bounded Patch 和 Review Closure

* 给修改范围生成稳定 anchor，并在 apply 前验证原文 hash/anchor 未漂移；
* 保护 snapshot 扩展到公式、表图 label、章节/假设编号和用户锁定片段；
* 提供显式 `apply` 和 `rollback`，仅处理已确认的 safe-fix；
* author-required 必须记录确认人、时间、理由和证据，不允许一个布尔开关直接放行；
* 强制 issue 状态迁移，只允许 `proposed → applied → verified → closed`；
* 从 ledger 派生 response letter 和 revision matrix，JSON/JSONL 仍是事实源。

验收：原文漂移、gate 失败或 apply 中断时可恢复；任何 issue 都不会因重跑、删除或直接
改 status 而无声消失。

#### R6：把“15/15”升级成能说明写作质量的 benchmark

建立 `evals/gold/`、`evals/mutations/` 和仅本地保存的 dogfood 工作区。最小覆盖：

* 中文经济学、中文管理学、英文经济学、英文管理学四象限；
* 引言、方法、结果/讨论、response letter；
* 正常文本、单一错误、多重错误、长篇全文和冲突语料；
* 至少 8 个不进入 Git 历史的真实/匿名任务，其中至少 2 个长篇、2 个返修任务；
* 每个 detector 同时报告 true positive、false positive、false negative 和适用范围；
* 对作者声音、论证清晰度、期刊适配和保守性使用人工 rubric，不伪造自动总分。

benchmark 必须实际计算发布门槛的分子/分母，不能把“测试脚本成功退出”写成
“方法越界检出率 100%”或“虚构引用率 0%”。

#### R7：收口 Router、能力声明和分发真实性

* 为 Router 2.0、capability report、workspace/checkpoint 增加 schema 和 valid/invalid fixture；
* 下游只读取已确认 route card，记录 override，不重复猜测学科、方法或期刊；
* 将 SKILL frontmatter description 压缩到不超过 1024 字符，并把 Skill Creator
  `quick_validate.py` 纳入 CI；
* 给外部 adapter 建立逐组件 provenance/permission/commit/license manifest 和 repro lock；
* 兼容性表改成 Verified / Documented / Conceptual，只有完成 smoke test 的 Agent 才标
  Verified；
* 在至少 Windows 与 Linux 两个环境运行 repository contract、三套测试和一个真实
  LaTeX compile 路径。

### 0.6 暂不进入下一阶段的工作

在 R1–R7 的 P0 闭环通过之前，以下内容不应抢占优先级：

* 更多通用科研 skill 或更大的方法目录；
* 默认多代理和自动研究循环；
* 付费数据库/CNKI 的“概念性支持”宣传；
* 大规模预置期刊 profile 库；
* Office、OCR、图表视觉审计和复杂版式复现；
* 以 star、skill 数量或 agent 数量为卖点的功能扩张。

### 0.7 v3.1 从 alpha 进入 beta 的最小条件

只有同时满足以下条件，才建议将版本从 alpha 提升为 beta：

1. R1 的端到端闭环可运行、可恢复，默认不覆盖原文；
2. R2 的每个新增外部主张都具有 source/locator/scope/status；
3. R3 能阻断无授权、过期、小样本和原句泄漏，并完成至少一次真实章节适配；
4. R4 覆盖计划中的核心方法组，并同时报告负例检出和正常例误报；
5. R5 的 anchor/apply/rollback/issue transition 全部通过失败注入测试；
6. R6 至少完成 8 个本地真实/匿名 dogfood 任务，并保留人工 rubric 与失败样例；
7. v3.0 18 项回归、v3.1 新评测、仓库契约、Skill Creator 标准校验和至少一个真实
   LaTeX compile 全部通过；
8. README、SKILL 和兼容性表只把实测能力标为 Verified。

上述条件全部满足之前，当前 `15/15` 只能解释为“已实现的 15 个合成契约检查通过”，
不能解释为“v3.1 的写作效果已经达到发布质量”。

## 1. 一句话产品定义

v3.1 是一个“懂经管论文论证、能按目标期刊调整表达、能保护作者事实、能把审稿意见变成可核验修改”的写作助手。

它不替作者发明研究结果，不替作者决定识别策略，不把一段风格模仿包装成学术贡献，也不在没有来源、全文或原始数据时假装完成文献核验或真实复现。

## 2. 为什么 v3.0 还需要升级

v3.0 已经完成了可靠性核心：路由卡、能力声明、证据包、数字/引用/LaTeX 审计、方法安全层、14 个职责化 reference 包、检索适配器和基础评测。但从“写一篇经管论文”的用户任务看，仍有五个明显断点：

1. **段落诊断不够论证化**：可以润色句子，却不能稳定指出一段是在提出问题、定位缺口、解释机制还是解读结果。
2. **期刊适配仍偏静态**：有 journal card，但缺少从目标期刊近期论文中提取风格 profile、记录冲突并在修订时复用的流程。
3. **方法安全与文字修改没有完全接通**：能提醒 DID/IV/RD 风险，但风险没有进入具体句子的改写、证据绑定和返修日志。
4. **审稿意见没有形成闭环**：风险清单和修订矩阵能列事项，但不能严谨地表达问题如何裁决、谁需要确认、修改后如何验证。
5. **写作质量缺少面向错误的 benchmark**：需要测事实保持、claim–evidence 对齐、过度因果语言、风格适配和作者声音，而不能只测文本是否流畅。

v3.1 不以“再增加几十个 skill”解决这些问题，而是把现有能力串成一条写作闭环：

~~~text
intake/router
  → paper spine 与 claim–evidence map
  → 方法安全和文献证据诊断
  → 目标期刊 style profile
  → 段落/章节候选修改
  → 数字/变量/引用/LaTeX/含义验证
  → reviewer issue ledger 与 revision log
~~~

## 3. 设计原则

### 3.1 写作优先，而不是研究平台优先

任何新模块都必须说明它改善哪一种写作结果：

* 让主张更清楚；
* 让段落逻辑更完整；
* 让方法表述更安全；
* 让证据和引用更可追溯；
* 让目标期刊适配更可解释；
* 让返修动作可记录、可回滚、可复核。

只改善“搜索更多、调用更多 agent、加载更多 skill”，但不能改善上述结果的能力，不进入 v3.1 P0。

### 3.2 P1 保护字段不可被润色覆盖

默认保护：

* 数字、单位、系数、p 值、置信区间、样本量；
* 变量名、处理定义、估计量、模型符号；
* 引用键、作者年份、DOI、表图编号；
* 公式、假设编号、章节标题和用户明确标记的句子；
* 作者的研究结论、贡献定位和局限性。

所有修改先生成保护字段快照，再产生候选 diff；任何保护字段改变都必须停止自动应用并要求作者确认。

### 3.3 证据和方法服务于写作

文献检索的最小单位不是“找到很多论文”，而是“为当前主张找到可用、可定位、范围清楚的证据”。方法诊断的最小单位不是“推荐一个方法”，而是“让方法段落准确说清数据、识别、估计量、假设、威胁和不能解决的问题”。

### 3.4 默认克制，能力分档

默认运行串行、离线、少上下文、少修改。网络检索、PDF 解析、外部模型和并行 agent 都是显式开关。能力状态继续沿用 Verified / Documented / Conceptual，并补充权限、版本、最近测试日期和降级路径。

## 4. v3.1 P0 功能包

### 4.1 Manuscript Router 2.0

路由对象不再只回答“这是什么学科”，还要回答“作者当前要完成哪一种写作动作”。

~~~yaml
task_mode: polish | diagnose | adapt | review | revise | audit
discipline: economics | management | finance | accounting | mixed
subfield: applied-micro | strategy | marketing | ob-hr | optional
language: zh-CN | en-US | bilingual
section: introduction | literature | theory | method | results | discussion | response-letter
method: optional
target_outlet: optional
preservation: strict | standard | user-defined
evidence_mode: offline | metadata | web-verified | user-provided-fulltext
execution: serial
user_overrides: []
confidence: medium
~~~

路由输出必须包含判断依据、置信度、未确定字段和可覆盖字段。下游模块只读取这张卡，不重复猜测。混合学科允许多标签，中文/英文只影响交付，不改变证据和方法红线。

### 4.2 Paper Spine 与 Claim–Evidence Map

借鉴全流程研究项目的阶段产物，但收敛为写作对象：

~~~yaml
paper_id: paper-001
research_question: ...
main_claim: ...
contribution_chain:
  - claim_id: c-001
    claim: ...
    section: introduction
    evidence: [e-001, e-002]
    method_dependency: [m-001]
    risk: medium
open_questions:
  - ...
~~~

每条 claim 都能追到证据、方法依赖和对应章节。它不是替作者发明论点，而是把作者已有文本显式化，方便诊断“主张超过证据”“贡献没有被结果支持”“讨论段落重复引言”等写作问题。

P0 只要求文本、表格和用户提供的结果作为证据；原始数据复现仍属于 v3.0 明确的能力边界。

### 4.3 Dynamic Journal Adaptation

v3.1 将现有 journal card 升级成两阶段、写作安全优先的动态适配。

#### Phase A：语料分析

输入可以是官方作者指南、用户提供的目标期刊论文、领域/主题论文和作者自己的范文。每份材料进入 corpus manifest，记录来源角色、文件 hash、可读性、许可状态和用途。

输出：

* 单篇 style card；
* 聚合 style profile；
* 冲突表、样本量、置信度、核验日期和过期日期；
* 不可读取或未授权材料的 rejection log。

提取内容只限于：

* section 顺序和常见论证动作；
* 段落长度的范围和分布；
* 文献引用位置与密度；
* 方法、结果和局限的叙述顺序；
* 图表引入和经济意义解释的结构；
* 中文/英文术语、语态和标题风格的统计性观察。

#### Phase B：有限修订

修订阶段只读取 dynamic writing profile、当前章节、paper spine、证据账本和保护字段快照，不重新把整套语料注入上下文。规则优先级固定为：

~~~text
P1 事实/引用/方程/符号/数字保留
> P2 目标期刊风格
> P3 领域或主题风格
> P4 项目静态写作规则
> P5 模板化语言清理
~~~

任何与 P1 冲突的“更像目标期刊”建议都必须放弃。禁止从语料复制原句、独特比喻、发现、结论或引用段落；语料只能提供结构和修辞层面的建议。

### 4.4 Argument & Method-Safe Writing Diagnosis

方法安全不独立于写作。每个诊断应给出四层结果：

1. 原句/原段的风险定位；
2. 触发的识别假设或证据边界；
3. 保守改写候选；
4. 需要作者补充的数据、稳健性或方法文献。

方法卡统一使用：

~~~text
数据结构
→ 识别变异
→ 目标估计量
→ 关键假设
→ 可诊断威胁
→ 适用估计方法
→ 不能解决的问题
→ 报告要求
→ 权威来源与核验日期
~~~

v3.1 P0 重点补充：

* 分期实施 DID 与异质性处理效应；
* 连续处理和剂量反应；
* Bartik/shift-share；
* CATE 与探索性异质性；
* 描述性中介与因果中介；
* quantile/Oaxaca 等分解；
* Survey、实验、定性和混合方法的独立写作质量门槛。

固定负例：

* 把 event-study 写成“证明平行趋势”；
* 把 PSM、控制变量或 Heckman 写成自动解决内生性；
* 把统计显著写成经济意义重要；
* 把中介回归写成已经证明因果机制；
* 把局部效应写成总体或外部有效性结论；
* 把摘要/元数据写成全文方法证据。

### 4.5 Evidence Ledger for Writing

证据账本的最小记录如下：

~~~json
{
  "claim_id": "c-021",
  "claim": "本研究识别的是处理组在处理时点附近的局部效应",
  "source_id": "s-008",
  "title": "...",
  "doi": "10.xxxx/xxxxx",
  "url": "https://doi.org/10.xxxx/xxxxx",
  "accessed_at": "2026-08-03",
  "verification_level": "abstract",
  "locator": {"page": 3, "section": "Identification"},
  "support_scope": "method-background-only",
  "limitations": ["不支持外部有效性结论"],
  "allowed_use": ["literature-review", "method-diagnosis"],
  "status": "verified"
}
~~~

“新增引用可追溯”必须具体到 claim/source/locator/support scope，而不是只在回答末尾给一个搜索结果链接。只有 metadata 或 candidate 状态时，正文措辞必须保持不确定。

### 4.6 Reviewer Issue Ledger 与返修闭环

把 v2 的风险清单、修订矩阵和 PaperJury 的 issue lifecycle 合成一个写作对象：

~~~json
{
  "issue_id": "iss-017",
  "source": {"kind": "reviewer", "id": "R2-C3", "locator": "p4"},
  "statement": "事件研究图被表述为证明平行趋势",
  "category": "method-safety",
  "severity": "major",
  "decision": "author-required",
  "proposed_action": "改为诊断性表述并补充假设与稳健性说明",
  "preserve": ["numbers", "variables", "citations"],
  "status": "triaged",
  "history": []
}
~~~

状态：

~~~text
raised
→ triaged
→ safe-fix / author-required / invalid
→ proposed
→ applied
→ verified
→ closed
~~~

安全修复可以是措辞、格式、交叉引用和机械一致性；涉及识别、理论、结果解释、数据处理或贡献定位的修改默认 author-required。任何 issue 都不能在没有验证记录的情况下直接关闭。

### 4.7 Bounded Writing Patch

候选修改不是直接覆盖原文的“重写结果”，而是带保护条件的 patch：

1. 固化数字、变量、引用键、公式、表图编号和用户标记文本；
2. 用唯一 anchor 锁定修改范围；
3. 标记风险级别；
4. 输出原文、候选文本、理由、对应 issue/claim、需要的证据；
5. 通过数字/引用/LaTeX/变量审计和语义检查后才允许作者接受；
6. gate 失败时回滚并保留失败日志。

默认只生成 diff。即使是 safe-fix，也应提供一条显式的 apply 命令或用户确认点。

## 5. 写作之外的支撑能力：只做最小版本

### 5.1 文献检索与 RAG

## 7. 写作评测体系

### 7.1 评测集组成

覆盖：

* 中文经济学、中文管理学、英文经济学、英文管理学；
* 引言、文献综述、理论/假设、方法、结果、讨论、结论和 response letter；
* DID、分期 DID、IV、RD、面板、Bartik、survey、实验、定性和中介；
* 正常文本、轻微问题文本和故意植入错误的文本；
* 短段落和长全文；
* 静态 journal card、真实用户提供语料和小样本/冲突语料。

### 7.2 v3.1 alpha 发布门槛

| 指标 | 目标 |
|---|---:|
| 轻润色数字/变量/引用键保持率 | 100% |
| 公式、表图编号和 LaTeX 交叉引用保持率 | 100% |
| 虚构参考文献率 | 0% |
| 新增 claim 的 source/locator 绑定率 | 100% |
| 方法越界表述检出率 | ≥95% |
| 表文数字错误检出率 | ≥95% |
| 期刊 profile 过期/样本不足拦截率 | 100% |
| 语料原句或独特发现复制率 | 0% |
| review issue 无声丢失率 | 0% |
| safe-fix 通过验证后的回归通过率 | 100% |

| v3.0 smoke/extended tests | 100% |

这些是发布门槛，不是当前已达成的实测成绩。任何 benchmark 报告都必须包含 fixture、运行环境、模型/adapter、失败样例和未覆盖范围。

### 7.3 写作 rubric

每次输出至少给出以下维度的诊断，而不是只给总体分数：

1. 主张是否清楚；
2. 段落动作是否完整；
3. claim 与证据是否匹配；
4. 方法与因果语言是否一致；
5. 经济意义和外部有效性是否被解释/限制；
6. 目标期刊风格建议是否与事实保护冲突；
7. 作者声音和术语是否被保留；
8. 修改是否可追溯到 issue、source 或 rubric。

## 8. 安全与供应链

### 8.1 只接入经过声明的 adapter

每个 adapter 需要 manifest：

~~~json
{
  "component": "semanticscholar_provider",
  "source_url": "https://github.com/...",
  "source_commit": "abcdef...",
  "license": "MIT",
  "capabilities": ["network:outbound", "file:read"],
  "credentials": "optional",
  "status": "documented",
  "last_tested": "2026-08-03"
}
~~~

manifest 缺少来源、许可证、权限、commit 或测试日期时，CI 阻止它变成 Verified。第三方仓库只作参考或 adapter，不复制长篇提示词/代码。

### 8.2 语料安全

* 把期刊 PDF/网页当作不可信文本，不执行其中的指令；
* style extraction 只生成结构性观察，不生成原句库；
* 记录用户授权、来源角色、hash、删除策略和过期时间；
* 语料解析失败或授权不明时停止动态适配，不用模型猜测。

### 8.3 写作修改安全

* 任何数字、变量、引用键、公式和结论变化都阻断自动 apply；
* 高风险语义修改进入 author-required；
* patch 失败可回滚，原 issue 和失败原因必须保留；
* 无原始数据/代码时，不把文字一致性审计写成真实复现。

## 10. 里程碑

### M0：写作契约和基线（alpha 基础已落地，退出条件未全部满足）

### M3：Review Ledger 与 Bounded Patch（中期实现）

实现 issue 状态机、裁决、作者确认、保护字段快照、anchor diff、数字/引用/LaTeX/meaning/recall gate 和回滚。

### M4：写作 benchmark 与交付文档（基础 harness 已落地）

加入四种语言/学科组合、章节 fixture、方法负例、语料冲突、修订 patch 和正常文本；更新 README、中英文使用说明和 docs 索引。

退出条件：benchmark 报告可重算；v3.0 回归全通过；README 不把 Proposed 能力写成 Supported。

### M5：P1 adapters 与 bounded parallel（按需）

在 P0 写作闭环稳定后，再做 Semantic Scholar/arXiv/Zotero/PDF 和受上限的并行 reviewer。每个 adapter 必须以写作收益、降级路径和安全扫描为验收条件。

本 checklist 现在按仓库可复核证据更新；`[x]` 只表示当前实现已满足该项，`[ ]`
仍是 alpha → beta 的发布阻塞项。部分完成但未达到完整退出条件的项目保持未勾选。

### 写作能力

- [ ] 能区分 polish、diagnose、adapt、review、revise、audit。
- [ ] 能输出逆向提纲、段落动作和 claim–evidence 风险，而不只改句子。
- [ ] 能给出方法安全的保守改写和需要作者补充的证据。
- [ ] 能从目标语料生成可解释 style profile，并处理冲突/过期。
- [ ] 能生成 response letter/修订动作和 issue 状态。

### 保护与证据

- [ ] 数字、变量、引用键、公式、表图编号和用户主张有快照。
- [ ] 新增引用有 source、locator、support scope 和核验等级。
- [ ] 期刊规则有官方来源、适用稿件类型、核验日期和 stale 状态。
- [ ] 语料只用于结构/修辞，不复制原句、发现或结论。
- [ ] 无数据/代码时不会声称完成真实复现。

### 工程交付

- [x] v3.0 smoke/extended 本地回归通过，CI workflow 已纳入三套离线测试。
- [ ] Skill Creator `quick_validate.py` 通过；当前 frontmatter description 超过 1024 字符。
- [ ] 所有 v3.1 新脚本都有 help、退出码、JSON 输出以及独立 valid/invalid fixture；
  当前核心 safety gate 已覆盖，但 schema、provenance 和迁移失败 fixture 尚不完整。
- [ ] safe-fix 通过所有保护审计；高风险修改转 author-required。
- [x] 离线基础审计不依赖网络、凭据或可选包。
- [ ] 外部 adapter 有来源、许可证、能力、commit 和测试日期。
- [ ] README 将已实现、Documented 和 Proposed 分开。

## 13. 最终判断标准

如果 v3.1 做完以后，作者仍然需要手工回答“这句话的证据是什么、这个方法表述是否越界、目标期刊的风格建议从哪里来、审稿意见改到哪一步、数字是否被改动”，那么升级没有完成。

如果系统可以让作者在一份工作区里看到这些信息，并且任何高风险修改都能回到原文、原 issue 和验证报告，那么即使它没有一千个 skill、没有几十个并行 agent、也已经完成了对写作 Skill 最有价值的升级。
